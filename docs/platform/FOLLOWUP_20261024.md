# 问题跟进：依赖、原生数值与 KITTI

日期：2026-10-24。原版基线仍为 UP `52aaeb9e`，工作分支为 `codex/up-platform-clean`。
本轮没有改 `up/` 模型和 `configs/` 配方，没有放宽 `rtol=1e-4, atol=1e-5`，没有恢复旧多种子任务。
用户另外批准修正 KITTI 评估器：**这个指标修复允许改变错误的原版数值，不属于重构等价通过。**

本文件记录该阶段的结果。随后已单独定位并修复 Faster R-CNN 的 RoIAlign 反向非确定性，见 [后续报告](FRCNN_DETERMINISM_20261024.md)；下文原失败记录保留。

## 已修正的错误处理

- `e1cd8e3`：可选 SDK 导入时主动 `SystemExit`，现在转换为包含依赖名称和原始原因的错误；能力查询返回不可用。
- MSBench 构建前核对请求的 `fake_sparse`、`mask_generator`，缺项立即报错。不把 `FakeSparse` 偷换为 `DefaultFakeSparse`，也不修改配方。
- 两家真实 MSBench Ampere 2:4 路径回归通过：29 个张量、实际更新、mask 和恢复、直接/路由比较。
- Amba 直接与路由两条路径仍失败。固定的 [公开 MSBench](https://github.com/ModelTC/msbench/blob/b00632036c8a03cacff6ae94814195e98f1361f8/msbench/prepare.py) 不包含原 UP 配方要求的 `FakeSparse`；没有确认等价的公开历史实现。
- [linklink](LINKLINK.md) 仍缺真实 SDK。找到的公开接口替代库不能证明通信、SyncBN、FP16 和三个融合优化器等价，没有用于冒充验收。

## 沐曦数值定位

新增 `tools/diagnose_platform_operator.py`（`a7478fe`），记录 ATen 调用、输入形状/dtype/stride/数值指纹、首个位差异和首个超容差差异。
完整参考张量留在真机证据目录。达到调用上限、启动失败或提前停止不能称为完整通过。

ResNet18 原版重复进程的结果：

| 位置，0 起始 | 操作 | 输入是否逐位相同 | 观察 |
| --- | --- | --- | --- |
| 48 | `aten.convolution.default` | 是 | 首个位差异，当时仍在容差内 |
| 56 | `aten.convolution.default` | 否 | 首次超容差，最大绝对差 `3.6239624e-05` |

把第 48 次卷积的真实输入单独交给 ATen，不导入 `up` 或 `up_platform`，执行 5 次：

| 启动环境 | 与第 1 次逐位相同 | 固定容差内 |
| --- | --- | --- |
| Torch deterministic + cuDNN deterministic + `CUBLAS_WORKSPACE_CONFIG=:4096:8` | 0/4 | 4/4 |
| 再增加下述两个 MCDNN 开关 | 4/4 | 4/4 |

这证明当前环境存在可脱离 UP 复现的卷积非确定性，小差异随后可能放大；不是“所有问题都来自 GEMM”的证据。
两组首个输出与原始捕获参考也都在原容差内。

```bash
# 只在启动新进程前显式设置；本分支没有自动设置这些变量
export MCDNN_USE_DETERMINISTIC_ALGO=1
export MCDNN_STABLE_RESULT_MOD=1
```

这两个名字来自当前 MACA 3.8.1.3 的 `libmcdnn.so`；目前没有核实到正式公开的稳定 API 保证。
本轮验证的是**组合设置**在该 SDK 上的效果，不声称单个开关的内部算法、跨版本保证或性能零开销。
没有新 GEMM/DNN 内核、FP64 训练、CPU 模型代算或旧 v1/v2/portable 策略。

## 显式 DNN 控制下的模型对照

同一平台的原版、原版重复、路由版三者使用相同环境开关。
实际 UP ModelHelper、原网络/损失/优化器、seed=131、batch=2、3 次更新；每步 eval，第 2 步后重建并恢复。
独立推理使用新进程和同一份原版 checkpoint。**合成输入，不是完整 Runner、数据集精度、收敛或性能测试。**

| 沐曦模型 | 原版重复训练/eval/恢复 | 路由训练/eval/恢复 | 原版重复独立推理 | 路由独立推理 |
| --- | --- | --- | --- | --- |
| ResNet18 | 通过 | 通过 | 通过 | 通过 |
| YOLOv5-S | 通过 | 通过 | 通过 | 通过 |
| ViT-B16 | 通过 | 通过 | 通过 | 通过 |
| PointPillar | 通过 | 通过 | 通过 | 通过 |
| Faster R-CNN R50 FPN | 未通过 | 未通过 | 通过 | 通过 |

Faster R-CNN 训练的原版重复和路由分别有 579、577 个比较项超容差；没有删除失败或取最好一次。
这些结果不能覆盖 [2026-10-23 默认原生路径的失败记录](VALIDATION.md#模型兼容性)，也不能证明其他形状/AMP/真实数据训练通过。
原版 UP 没有 DETR 配方，本分支没有额外插入 DETR 模型冒充原版兼容性。

NVIDIA Faster R-CNN 也追加了定位：首个位差异在调用 1840 的 `aten.add.Tensor`，其输入已不同；
首次超容差在调用 1956 的 `aten.convolution_backward.default`，其输入也已不同。
因此不能据此把卷积反向认定为根因。ATen 跟踪不能看见直接 pybind CUDA 内核内部，还需要继续定位此前的专用扩展边界。

## 复现原生数值定位

先按 [环境说明](ENVIRONMENT.md) 配置对应厂商 Torch/SDK 和固定依赖，使用已分配的 GPU。
`BASE` 必须是原版 UP `52aaeb9e` 的独立源码目录，不能用重构版替代。

```bash
export PYTHONPATH="$ROOT:$DEPS:$MQBENCH:$MSBENCH:${PYTHONPATH}"
export OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 PYTHONHASHSEED=0 DEFAULT_TASKS=cls:det
export CUDA_VISIBLE_DEVICES=0 CUBLAS_WORKSPACE_CONFIG=:4096:8
# 容器 uid 没有 passwd 条目时，另外显式设置 USER/LOGNAME

# 原生定位：先不加两个 MCDNN 变量；输出目录不能已存在
python "$ROOT/tools/diagnose_platform_operator.py" --root "$ROOT" --baseline "$BASE" \
  --vendor metax --model resnet18 --variant original --limit 1200 --output "$OUT/original"
python "$ROOT/tools/diagnose_platform_operator.py" --root "$ROOT" --baseline "$BASE" \
  --vendor metax --model resnet18 --variant repeat --limit 1200 \
  --reference "$OUT/original" --output "$OUT/repeat"
python "$ROOT/tools/diagnose_platform_operator.py" --capture "$OUT/repeat/first-bitwise.pt" \
  --repeats 5 --output "$OUT/replay-native.json"

# 新进程中启用已测组合，保存为另一份报告，不覆盖 native 结果
export MCDNN_USE_DETERMINISTIC_ALGO=1 MCDNN_STABLE_RESULT_MOD=1
python "$ROOT/tools/diagnose_platform_operator.py" --capture "$OUT/repeat/first-bitwise.pt" \
  --repeats 5 --output "$OUT/replay-controls.json"
python "$ROOT/tools/compare_platform_models.py" --root "$ROOT" --baseline "$BASE" --vendor metax \
  --models resnet18 yolov5s vit_b16 faster_rcnn pointpillar --deterministic \
  --reference-defer-kitti --output "$OUT/models-controls"
```

`.pt` 捕获只加载自己产生且可信的证据。独立重放当前仅接受纯卷积/矩阵操作，不假装支持有别名写入或随机状态的任意算子。
预期 Faster R-CNN 仍导致模型总入口非零退出；不能把这个命令描述为全套通过。
三步模型协议不调用 KITTI 指标，后续评估器修正不改上述结果。
