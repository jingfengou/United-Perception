一套 UP，接不同厂商的显卡

这次改造把硬件调用从 UP 中抽到平台层。下面沿着设计、代码和实际命令，讲清它做了什么、怎样实现，以及怎么使用和扩展。

01

先看设计：算法留在 UP，硬件交给平台

原版 UP 的设备调用和专用算子散在模型、训练与推理里。现在把这些入口集中到 up_platform/；换厂商时，实现平台接口即可。

部分这次做的事
UP 主体
up/、configs/		模型、损失、数据和配方继续由 UP 管理；硬件调用改接平台，原算子的导入路径和 .apply() 入口保留。
统一平台
up_platform/		新增设备、15 类算子、训练和推理接口；各厂商显式实现或绑定，共用兼容代码。训练补入 FSDP2 分片能力。
安装与切换
docker/unified/、up_docker		一份镜像隔离 NVIDIA 与沐曦环境，一条命令选择厂商和任务。
接入与维护
tools/、tests/platform/		生成新厂商模板，检查接口、上层调用和文档，并提供算子及模型流程评测代码。

为什么设备、算子、执行方式并列？
它们是平台的三个组成部分。训练和推理都会用设备与算子，所以这些共用能力放在外面。

训练内 eval 为什么还走训练后端？
它复用正在训练的模型，验证结束后继续训练。独立推理才选择另一套执行接口。

基础加减、索引、拼接、reshape、归约和 autograd 仍由厂商 PyTorch 提供。

15 类采用同一结构：父类定接口，厂商文件显式绑定，兼容实现共用。

03

最后使用：同一镜像，一条命令选厂商

下面用 YOLOv5-S + COCO 2017。命令在 Linux Bash 中运行；宿主机需要 Docker 和对应显卡驱动，NVIDIA 还需 Container Toolkit。

1

构建镜像

git clone --branch codex/up-platform-clean \
  https://github.com/jingfengou/United-Perception.git
cd United-Perception
docker build -f docker/unified/Dockerfile -t up-unified:local .

镜像内 /opt/up/envs/nvidia 和 /opt/up/envs/metax 分开安装 PyTorch、SDK 与扩展。

2

设置数据和工作目录

export UP_DATA=/datasets/coco2017
export UP_WORK=$HOME/up-demo
export UP_GPU=0
mkdir -p "$UP_WORK/images"

sed 's|coco/|/data/|g' configs/det/yolov5/yolov5_small_silu.yaml \
  > "$UP_WORK/model.yaml"
cp configs/det/yolov5/anchors.json "$UP_WORK/anchors.json"
cp "$UP_DATA/val2017/000000000139.jpg" "$UP_WORK/images/"

COCO 目录包含 train2017/、val2017/ 和 annotations/。

3

选厂商，运行任务

训练后再运行验证或推理。命令会读取当前厂商的 ckpt_latest.pth；重跑训练想从头开始时换一个输出目录。

安装细节与多卡参数见 完整运行指南；分片训练见 FSDP2 指南。

04

怎样扩展：以新厂商 acme 为例

新增厂商的工作集中在平台实现与运行环境。先准备厂商 PyTorch、SDK 和通信库；如果还没有 PyTorch 设备后端，先接通设备、张量、算子派发和 autograd。

1

按父类生成要交付的文件

python tools/new_platform_vendor.py \
  --vendor acme --device privateuseone --output acme_platform --reuse-torch

acme 和 privateuseone 替换为真实厂商、设备名。已确认兼容 Torch 公共 API 时使用 --reuse-torch。

acme_platform/
  __init__.py       组装设备、算子与当前用途，注册 build
  device.py         厂商身份、SDK 检查与设备操作
  training.py       AMP、多卡、优化器、验证、保存恢复
  inference.py      推理 autocast 与导出
  ops/              15 类算子，类别与上面的图一致
2

兼容的直接绑定，有差异的单独实现

生成器已为常见 Torch 类别写好绑定。以 ops/matrix.py 中的一个函数为例，选择一种方式：

# 复用当前厂商的 PyTorch
from up_platform.ops.matrix import torch_impl
AcmeMatrixOps.linear = staticmethod(torch_impl.linear)

# 若这个函数要使用厂商 SDK，替换这一项绑定
from .. import vendor_kernels
from up_platform.templates.sdk_linear import bind_sdk_linear
AcmeMatrixOps.linear = staticmethod(bind_sdk_linear(vendor_kernels))

使用 SDK 时，在插件根目录增加 vendor_kernels.py，提供 linear_forward 和 linear_backward。linear 函数与 Linear 层是两个入口；两者都受影响时分别适配。其余类别按父类签名逐项处理。

3

让 UP 使用新厂商

将生成的包安装到厂商环境，或把它的父目录加入 PYTHONPATH。生成器已写好注册，YAML 选择：

runtime:
  platform:
    backend: acme
    device: privateuseone
    plugins: [acme_platform]
    requirements: [matrix.linear, convolution.Conv2d]

然后在该厂商环境启动 UP：

DEFAULT_TASKS=cls:det python -m up train \
  --config model.yaml --launch pytorch --ng 1

要加入 up_docker，再补镜像安装步骤、环境 profile 和显卡设备挂载。现有 NVIDIA、沐曦实现可作为参考。

4

检查接口，再测真实流程

python tools/platform_contracts.py
python tools/check_platform_boundaries.py
python -m pytest tests/platform -q

软件检查之后，在目标卡上测算子前向、所需反向和状态，再跑训练、训练内 eval、保存恢复和独立推理；多卡功能再测通信与同步。

完整函数列表见 接口定义；逐步接入见 厂商接入指南；SDK 反向接线见 Linear 示例。昇腾、寒武纪当前提供接入模板。
